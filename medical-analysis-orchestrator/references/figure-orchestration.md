# 图形编排与视觉质控契约

本契约把科研绘图分为四个阶段：图形意图、数据适配、R 生成、产物审计。它借鉴公开科研绘图工作流的治理思想，但不复制第三方代码；统计计算与图形生成仍以 R 为唯一事实来源。

## 1. 图形意图

每个已选模块由 `scripts/plan_figures.py` 生成一条图形计划，至少说明：

- 模块和 `figure_plan_id`；
- 证据角色，例如分布、组间比较、效应估计、诊断或纵向轨迹；
- 推荐图形族及选择理由；
- 必需的样本定义、中心统计量、区间、检验和多重比较字段。

图形计划不能代替主要结局确认，也不能从 P 值自动生成论文主张。用户可以在 `reporting.figure_plan.module_overrides` 中覆盖图形族和理由。

## 2. 数据适配

绘图前应使用同一运行的 `data_profile.json` 和 R 模块结果对象，核对：样本量、分组数、变量类型、缺失率、分布偏态、重复测量结构、单位和有效样本量。以下情形必须产生提示或拒绝：

- 小样本只画汇总柱状图而没有原始观测；
- 将无序分类水平用线连接；
- 双 Y 轴、饼图、三维图、彩虹/jet 色带；
- 用截断坐标、颜色或选择性标注夸大差异；
- 误差线未声明是 SD、SE、CI 或 IQR；
- 图形分母、缺失处理、分析集与表格不一致；
- 未经确认的显著性星号或成对比较；
- 面板之间变量编码、单位、颜色语义不一致。

## 3. R 生成边界

所有统计图形、预览和正式导出由 R 设备生成。PNG/TIFF 设备显式传入模板字体；SVG/PDF 保留可编辑文字。Python 只能读取现有图像进行尺寸、格式、DPI、路径和灰度可辨识性审计，或生成现有 PNG 的灰度复核副本，不得重绘、重新拟合或修改统计内容。

## 4. 视觉 QA

`scripts/figure_visual_qa.py` 生成 `90_最终报告/figure_visual_qa.json`，记录：

- R 生成边界、每张图的文件路径和导出格式；
- PNG 实际像素尺寸、格式、色彩模式与可读取 DPI；
- 结论、证据角色、Source Data 与完整统计元数据是否存在；
- 路径是否越过当前运行目录；
- 可选的灰度预览路径。

该 JSON 的 `fail` 表示契约缺失或文件损坏，`warning` 表示环境能力不足或像素规格偏小，`pass` 仅表示机器可验证条件通过，不等于完成医学解释或目标期刊的最终人工审稿。

## 5. 期刊版式

`journal_profile` 是保守的版式预设，不是对任何期刊最新指南的保证。真实投稿时，应根据目标期刊的最新作者指南覆盖版心、字体、图幅、DPI 和文件格式。
