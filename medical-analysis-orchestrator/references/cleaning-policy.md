# 数据清洗确认策略

## 可自动执行

以下操作只作用于新建的清洁副本，并必须写入日志：

- 复制数据到独立运行目录；
- 统一输出为 UTF-8 CSV；
- 去除变量名首尾空白和不可见字符；
- 为缺失或重复变量名生成唯一分析名；
- 保留原始行顺序并增加内部行序号；
- 将读取器已明确识别的物理空值写为标准缺失；
- 生成变量字典、质量报告和数据指纹；
- 把日期、数字和分类类型作为建议写入字典，但不自动强制转换。

## 必须用户确认

以下操作不得静默执行：

- 删除任何记录、重复记录、变量或异常值；
- 把 `-9`、`99`、`999`、`unknown` 等特殊值改为缺失；
- 合并或拆分类别，修改参照组；
- 文本转数字、连续变量离散化、日期解析规则；
- 单位换算、截尾、缩尾、对数或其他变换；
- 多文件合并、宽长表转换、聚合；
- 量表反向计分、总分或分量表计算；
- 缺失值插补或完整案例排除规则；
- 纳入排除标准；
- 主要结局、事件编码、时间起点和删失规则。

确认操作写入 `data_handling.confirmed_actions`，每项至少包含：

```yaml
- id: "recode_missing_001"
  action: "recode_to_missing"
  variables: ["age"]
  rule: "value == 999"
  reason: "数据字典规定 999 为未知"
  confirmed_by: "researcher"
  confirmed_at: "ISO-8601"
```

清洗日志至少记录操作 ID、变量、规则、影响行数、执行时间、执行前后指纹和状态。日志不得包含患者级原值。
